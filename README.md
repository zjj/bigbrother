# BigBrother

BigBrother 是一款 macOS 菜单栏应用，帮助你查看 App 何时使用了屏幕、麦克风、摄像头、位置、剪贴板及其他受保护的内容。

它还会尽量说明访问是由哪个 App 发起、由哪个程序实际操作。记录保存在本机，你可以查看访问记录、了解 App 与执行程序之间的关联、筛选内容或导出数据。

点击菜单栏图标可打开或收起面板。面板与菜单栏留有间距，按概览页的内容调整高度，最高不超过屏幕可用高度的四分之三，更多内容可滚动查看。

BigBrother 只记录和展示系统提供的信息，不会阻止访问，也不会保存屏幕画面、录音或文件内容。没有记录不一定代表没有访问。

菜单栏面板在初始化或采集未运行时显示「BigBrother is watching you」；概览下方会分别说明正在初始化或记录已中断，标语本身不代表采集已成功启动。

默认不申请通知权限；开启通知时才向 macOS 申请。导出记录时通过系统保存窗口选择位置，不需要完全磁盘访问权限。

## 如何理解记录

- **权限检查单独记录**：`preflight=yes` 且**没拿到授权**的查询才是纯检查，它不代表访问，也不计入使用统计。微信截图如果只留下这类日志，会出现在「权限检查」，不会冒充成功截图。
- **使用线索**：系统给了明确授权（允许或部分允许）的访问请求都算使用，**包括 App 早已获授权之后的那次访问**。系统在已授权状态下仍然为每次访问打授权日志，这正是「悄悄访问」唯一可观察的证据。分为两档：`preflight=no` 的请求（系统真的发起了采集）标为**已证实访问**；只有 `preflight=yes` 的授权查询标为**已授权访问（未证实采集）**——它证明 App 此刻在申请这项权限，但不证明已经拿到画面或录音。摄像头、麦克风、屏幕画面等都适用；屏幕画面只统计 replayd 像素通道，不把窗口信息查询算作截图。
- **活动信号**：剪贴板内容发生变化、系统定位服务开始向某个客户端供数，或 ScreenCaptureKit 报告录制开始。录制开始日志能对应到仍在运行的 App（校验进程名及启动时间），或同一进程邻近的屏幕权限记录时立即保存，不要求重新授权，也不等待结束；结束日志用于补充时长，且只补到「已证实访问」那一条上。没有结束日志不代表此刻仍在录制。剪贴板变化不代表前台 App 读取了内容。
- **摄像头还有第二条证据线**：实测 macOS 27 上一次微信视频通话，摄像头确实开启了（Control Center 标记 `com.tencent.xinWeChat` 摄像头活跃、`cameracaptured` 配置了 1920×1440 视频流），而 `tccd` **一条 `kTCCServiceCamera` 审计都没有**，只有麦克风的 AUTHREQ。所以摄像头除了 TCC，还采集 Control Center 自己的记录：某个 App 的摄像头模块变为活跃（也就是你看到菜单栏绿灯亮起的那一刻）。同一个 App 持续使用每 20 秒最多记一条，苹果自己的采集组件（`com.apple.cameracaptured`）不计入。
- **定位走的是另一条管线**：macOS 不为定位发 TCC 审计日志，证据来自 `locationd`：系统状态栏开始显示定位、坐标被投递给某个客户端、或该客户端获准开始供数。这三条按强度取最强的一条，同一个 App 持续定位每 20 秒最多记一条。它证明系统向该 App 提供了位置信息，但不含坐标，也不代表读取了具体地点。苹果自己的位置组件（`CoreParsec.framework`、`Routine.bundle`、`CoreWLAN.framework` 之类）不是 App、也没有归因到某个 App，因此不进记录——它们是系统自己的位置机制，混进来只会把真正要看的 App 挤下去；`--locscan` 会显示跳过条数。
   值得注意的是 `locationd` 的 `computing freshAuthorizationContext` 不是使用证据：实测 Google Chrome 真的拿到坐标时，这一行的 `InUseLevel` 仍是 `NotInUse`。旧版只认这一条，等于完全看不到定位使用。
- **不确定时不推断使用**：结果缺失、被拒绝、未知权限类型保存在「未确认或被拒请求」，不计入使用统计。没有可确认访问者的录屏日志写入诊断日志，不猜测是哪一个 App。

记录页可按「记录类别」筛选,五项互斥、加起来就是全部证据:

- **访问记录**(默认):系统能确认的访问 —— 已证实的采集动作,加上已授权状态下的访问。概览、关联、下钻、眼睛颜色和通知都只用这个口径。
- **只有动作**:更硬的一层,只保留剪贴板变更、系统向某个 App 供数、录屏开始/结束这类实际动作。
- **仅权限查询**:App 问过权限,而系统没有给出授权。不计入统计、不发通知,但照旧入库可查。
- **被拒或未知**:授权结果缺失或被系统拒绝的请求。
- **全部原始记录**:不做任何过滤,用于逐条核对。

概览与下钻用同一个时间窗,所以数字一定对得上。导出可选择上面任一范围,默认导出全部,并附上阶段、授权结果、证据强度、证据说明、是否计入使用统计及原始服务名。历史记录里的权限查询不会由代码自动删除。统计是证据条数,不是成功截图、录音或读取次数;一次录制可能同时产生访问线索与活动证据。BigBrother 自己的有效访问不会隐藏。

**已授权不豁免记录，但无法保证全量访问审计。** 摄像头、麦克风和个人数据目前主要依赖系统权限调用日志；已授权后如果系统不再发出可观察日志，就可能漏报。录屏活动通道仅覆盖系统实际输出的 ScreenCaptureKit 录制生命周期日志，不覆盖所有截图 API 或所有屏幕流。剪贴板读取、具体文件读取以及每次摄像头/麦克风启停，目前不支持完整的逐 App 审计。不能仅凭 WindowServer 或 replayd 通道名判断是否成功截图。日志采集包含 info/debug 级别，但系统可能隐去身份或不保留日志，轮询也无法恢复未保存的内容。没有记录绝不等于没有访问。

新的 Apple 专属事件不再入库：系统日志中的责任主体和实际执行者都属于 `com.apple.*` 时忽略。只要其中一方是第三方程序，仍保留事件；请求通道由 Apple 系统组件处理（例如微信通过屏幕采集服务）不影响记录。已有记录不会自动删除或隐藏；如果需要清除历史记录，请先退出应用，再自行处理本地数据库及其附属文件。

“完全磁盘访问”是权限类别，不代表访问了所有文件。系统没有提供目标文件时，应用不会猜测文件路径。不应仅为消除这些记录而授予完全磁盘访问权限。

旧记录会在新版首次启动时按上述口径**重新判定**：只重算严重度与判定说明，原始授权值、`preflight`、时间等证据一字不改，也不删除任何行。因此升级后历史记录里已经获授权的访问会重新出现在统计中。旧版已经折叠在同一行的不同阶段记录无法从现有数据还原；新版会按阶段、授权结果及 `preflight` 分别折叠。

## 构建与运行

需要 macOS 13 或更高版本，以及 Xcode 命令行工具。

在项目目录运行：

```bash
make
```

应用会生成在 `dist/BigBrother.app`。构建并启动：

```bash
make run
```

生成可分发的磁盘映像：

```bash
make dmg
```

DMG 文件会生成在 `dist/BigBrother.dmg`。

默认使用本地签名。正式分发时可指定开发者签名身份：

```bash
make dmg CODESIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)"
```

公开分发还需完成 Apple 公证。

清理构建产物：

```bash
make clean
```

用日志文件运行命令行自检：

```bash
make test LOGS="/path/to/log.txt"
```

运行权限事件与存储回归测试：

```bash
make test-storage
```

排查定位记录时可以只跑定位通道（定位不走 TCC，单独一条管线）：

```bash
dist/BigBrother.app/Contents/MacOS/BigBrother --locscan <日志文件>…
```
